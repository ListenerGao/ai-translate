## 目标

- 在任何 App（浏览器、备忘录、微信、PDF 阅读器、编辑器……）里选中文字，按 `⌥D`，鼠标旁边弹出翻译卡片
- 卡片和插件的翻译卡片一致：上面是原文（长了可以展开），下面是译文，可以复制；能临时换目标语言、固定卡片（固定后点别处不关），按 `Esc` 或点 × 关闭
- `⌥A` 打开翻译窗口，光标停在输入框
- 快捷键可以在设置里改，和别的 App 冲突时提示

## 默认做法（不需要确认，有异议再说）

- **取词顺序**：先用辅助功能接口读选中的文字（不碰剪贴板）；读不到时模拟一次 `⌘C`，等剪贴板变化（最多 0.3 秒），取完把剪贴板恢复原样；都取不到（没选中文字）就什么都不做，不弹窗口也不提示（主人 2026-10-21 定，原定提示「没取到选中的文字」）
- **没有辅助功能授权时**：按 `⌥D` 弹出说明，为什么要授权、授权后能做什么，按钮直接打开系统设置的对应页面；同时提示不授权也能按 `⌥A` 打开翻译窗口粘贴
- **长度**：选中的文字最多 5000 字，超过时提示改用翻译窗口
- **通道**：走 `interactive`，和插件的划词一样排在批量任务前面
- **卡片**：出现在鼠标附近、不超出屏幕；点卡片外面就关闭（固定时不关）；不在 Dock 和 `⌘Tab` 里出现
- **隐私**：取到的文字只发给本机 aitd，不写日志，不存翻译历史

## 不做

- 朗读（以后可以用本机语音加）、截图翻译（OCR）、翻译历史、把译文替换回原文

- 模型下载和切换（Goal 8）
- 提交、推送（未经主人要求不做）

## 接口决策

- **全局快捷键**：用系统的 Carbon `RegisterEventHotKey`，注册快捷键本身不需要辅助功能授权；注册失败（被占用）时在设置里提示
- **读选中文字**：`AXUIElementCopyAttributeValue`（当前焦点元素的 `kAXSelectedTextAttribute`）；模拟 `⌘C` 用 `CGEvent`，两者都需要辅助功能授权，用 `AXIsProcessTrusted()` 判断
- **剪贴板恢复**：模拟 `⌘C` 前把剪贴板里所有项目、所有格式存下来，取完原样写回（原来是图片、文件也能恢复）
- **卡片窗口**：不抢前台 App 的 `NSPanel`；复制、换语言、固定、关闭都能用键盘操作

#### CP0 结果（2026-10-20 23:31）

为了实测，先写了 CP1、CP2 的核心（快捷键存取、Carbon 注册、辅助功能读取、模拟 `⌘C` 和剪贴板恢复，单测 8 条），加调试参数 `--probe <记录文件>`：每按一次 `⌥D` 两种方法各取一次，只记 App、成没成功、字数、耗时、错误码和焦点元素角色，不记文字内容。主人授权辅助功能后在常用 App 里试了 2 轮，共 13 次：

| App | 辅助功能接口 | 模拟 `⌘C` | 说明 |
|---|---|---|---|
| 文本编辑 | 1/1，16ms | 1/1，77ms | 两种方法取到的一致 |
| 预览（PDF） | 1/1，4ms | 1/1，62ms | 两种方法取到的一致 |
| Chrome | 0/2，8~17ms | 2/2，36~49ms | 取不到焦点元素（`-25212`，Chrome 默认不对辅助功能开放网页内容） |
| VS Code | 0/1，20ms | 1/1，44ms | 同上（Electron） |
| 微信 | 0/3，0~12ms | 3/3，34~37ms | 同上 |
| 公司 IM | 0/1，22ms | 1/1，44ms | 同上 |
| One | 0/4，0~43ms | 4/4，34~70ms | 焦点元素是 `AXScrollArea`，不支持「选中文字」属性（`-25205`） |

- **默认取词顺序不变**：先辅助功能接口（原生 App 能取到，不碰剪贴板），取不到再模拟 `⌘C`。辅助功能取不到时多花不到 50ms，两步加起来最慢约 0.12 秒
- 模拟 `⌘C` 13 次全部取到；主人确认试完后剪贴板恢复正常
- 不给 Chrome、Electron App 打开辅助功能树（`AXEnhancedUserInterface` / `AXManualAccessibility`）：会让这些 App 变慢、和窗口管理工具冲突，而 `⌘C` 已经能取到
- 重新构建（改代码、重新签名）后启动，辅助功能授权仍在，不用重新授权
- 已知问题（写进 README）：VS Code 里什么都没选时 `⌘C` 会复制整行，`⌥D` 会翻译当前行
- 没测到：Safari、备忘录、终端，CP2 验证时补上
