## 接口决策

### 目录

```
apps/server/src/
├── main.ts        启动入口：读配置、起 HTTP 服务、处理退出信号
├── http.ts        路由、鉴权、NDJSON 输出
├── model.ts       llama-server 进程管理：按需启动、就绪等待、崩溃拉起、空闲停止
├── cache.ts       SqliteCache（实现 core 的 CacheStore）
└── glossary.ts    术语表文件读写
packages/core/src/       新增 scheduler.ts（加 lane）、pipeline.ts、llama-server.ts、errors.ts、cache.ts（CacheStore 接口、MemoryCache）
apps/extension/src/background/aitd.ts   AitdTranslator：连 aitd 的 Translator 实现
scripts/aitd-service.sh  安装 / 卸载开机自启
```

### HTTP 接口

- `GET /health`：不需要密钥，返回 `{ "status": "ok", "version": "…" }`；弹窗用它判断 aitd 在不在
- `GET /api/status`：模型状态（`stopped` 已休眠 / `starting` 启动中 / `ready` 运行中 / `error` 出错，带原因）、模型和量化版本、槽位数、排队数、缓存条数
- `POST /api/translate`：请求体是段落协议的 `TranslateRequest`，另加两个字段：`lane`（`interactive` 给插件，`batch` 给命令行，默认 `interactive`）和 `priority`（越小越先，只在同一 lane 内比较）。返回 `application/x-ndjson`，每段一行，按完成顺序：`{"id","text","cached"}` 或 `{"id","error":{"code","message"}}`
- **撤销**：客户端断开连接，就撤销这个请求里还没开始的段落；已经开始的照常翻完并写缓存（和第一阶段一致）
- `GET /api/glossary`、`PUT /api/glossary`：纯文本，一行一条 `原文=译文`；PUT 先用 core 的 `parseGlossary` 校验，有错返回 400 和出错行号
- **调度**：全局一个队列，并发数等于 `llama-server` 的槽位数（4）；`interactive` 永远排在 `batch` 前面，同一 lane 内按 `priority`、再按先来后到
- **合并**：相同内容同时在翻时只翻一次（缓存键相同即合并，和第一阶段一致）
- **超时**：单段超时由 aitd 计时，从开始执行算起 30 秒；排队和等模型启动的时间不算

### 安全

- 只监听 `127.0.0.1`；除 `/health` 外都要带 `Authorization: Bearer <密钥>`，用定长比较防止按耗时猜密钥
- `Host` 头只能是 `127.0.0.1:8790` 或 `localhost:8790`，防 DNS 重绑定
- 带 `Origin` 头且来自网页（`http://`、`https://`）的请求一律拒绝；允许 `chrome-extension://` 和没有 `Origin` 的请求（命令行）
- 不返回任何 CORS 头
- 请求体上限 1MB

### 模型进程

- 启动参数沿用 `scripts/start-model.sh`（`-c 16384 -np 4 -ngl 99 --cache-ram 0 --reasoning off …`；`--cache-ram 0` 关掉提示缓存，见 CP0 结果，2026-10-19 13:02 脚本已加上），端口 8791，`--api-key-file` 指向 aitd 生成的一次性密钥文件；量化版本默认 Q8_0，可用环境变量 `AIT_QUANT` 改
- **按需启动**：第一个翻译请求到来时启动，轮询 `llama-server` 的 `/health` 直到就绪（最多等 60 秒）；启动期间进来的请求排队等待
- **崩溃**：子进程意外退出时，正在翻的段落返回 `server` 错误，下一个请求再拉起；1 分钟内连续启动失败 3 次，就停在 `error` 状态，`/api/status` 给出原因（`llama-server` 输出的最后几行）
- **空闲停止**：最后一次请求完成后 30 分钟没有新请求，就停掉 `llama-server`；再来请求时重新启动
- **退出清理**：aitd 收到 Ctrl+C 或 `SIGTERM` 时一并停掉 `llama-server`，不留孤儿进程
- **端口被占**（比如还开着 `scripts/start-model.sh`）：报「端口 8791 被占用」并停在 `error`，不去动别的进程

### 插件

- `LlamaServerTranslator` 换成 `AitdTranslator`：每段发一个 `POST /api/translate`，`lane` 为 `interactive`，`priority` 沿用视口距离，划词仍是 -1
- 插件后台保留自己的调度队列，并发 4，只发「轮到的」段落：Chrome 对同一地址最多同时开 6 个 HTTP/1.1 连接，一次发出几十段会在浏览器里排队，打乱视口优先级
- 去掉插件的 IndexedDB 缓存和「相同内容只翻一次」，都交给 aitd
- 插件端只留 120 秒兜底超时；正常超时由 aitd 判定
- 设置页：术语表改为读写 aitd；服务地址默认 8790
- 弹窗「模型」行：读 `/health` 和 `/api/status`，显示「运行中」「启动中」「已休眠（用到时自动启动）」「没连上 aitd」
- 错误提示：连不上 aitd 时整页提示「本机翻译服务没启动」，附启动方法；模型启动失败时显示 aitd 给出的原因

### 启动方式

- 开发和手动使用：`npm run aitd`，前台运行，日志同时打到终端
- 开机自启（主人授权后）：`scripts/aitd-service.sh install` 生成 `~/Library/LaunchAgents/com.listenergao.ai-translate.aitd.plist`（用户级，登录后启动，崩溃自动拉起）；`uninstall` 停止服务并删除 plist。plist 里写 Node 22 的绝对路径，不依赖终端环境

## 风险与对策
