## 目标

在终端里用本机模型翻译，内容不出本机：

- `ait "Hello world"`、`pbpaste | ait`：翻一段文字，译文打到终端
- `ait translate README.md`：翻 Markdown，标题、列表、表格、代码块、链接、加粗原样保留
- `ait translate talk.srt`：翻字幕，序号和时间轴不变
- `ait status`：看 aitd、模型和缓存的状态

所有请求都走 aitd 的 `batch` 通道：和浏览器共用缓存和术语表，同时使用时不拖慢浏览器里的翻译。

## 默认做法（不需要确认，有异议再说）

- **参数**：`--to` 目标语言（默认 `zh`）、`--from` 源语言（默认 `auto`）、`--glossary <文件>` 追加本次专用的术语，和 aitd 的术语表合并，冲突时以本次为准
- **退出码**：0 成功；1 参数或文件错误；2 aitd 没启动或密钥不对；3 有段落没翻成（这些段落保留原文，在 stderr 列出位置）
- **进度**：翻文件时在 stderr 显示「已完成 n / 总数」，只在 stderr 是终端时显示，不污染重定向的输出
- **密钥**：只从 `$AIT_HOME/api-key` 文件读；不支持用环境变量或命令行参数传密钥，免得进 shell 历史
- **字幕的 prompt**：和网页、插件用同一个纯文本 prompt，不加文体「字幕」和前后文（2026-10-19 21:09 按 CP0 实测改定，原定默认用文体「字幕」；对照页给主人复核）
- **缓存**：字幕和网页用同一套 prompt，同一句话的译文本来就相同，共用缓存；插件现有 prompt 逐字不变，已有缓存不失效
- **大文件**：段落按每批 200 段分批发给 aitd，不超过 aitd 的请求体上限

## 接口决策

### 目录

```
apps/cli/src/
├── main.ts        参数解析、子命令分发、退出码
├── client.ts      连 aitd：读密钥、发 batch 请求、读 NDJSON
└── files.ts       读写文件、输出命名、覆盖检查
packages/core/src/formats/
├── markdown.ts    Markdown 分段、行内标记、重组
└── srt.ts         SRT 解析、重组
scripts/install-cli.sh   安装 / 卸载 ~/.local/bin/ait
```

Markdown 和 SRT 的处理放进 `packages/core`：只做字符串处理，不依赖运行时，第三阶段桌面应用的「文章和字幕翻译」可以直接复用。

### 命令

```
ait [文字]                  翻译文字；不给文字时读标准输入
ait translate <文件>        按扩展名识别：.md、.markdown、.srt
ait status                  aitd、模型、缓存状态
通用选项：--to <语言>  --from <语言>  --glossary <文件>  --bilingual  -o <路径|->  --force
```

### Markdown

- **分段**：标题、段落（多行合成一行翻，翻完按原缩进写回）、列表项、引用、表格单元格
- **跳过**：围栏代码块、缩进代码块、front matter（文件开头 `---` 包住的 YAML）、HTML 块、链接定义行、只有链接或图片的行
- **行内格式**：加粗、斜体、链接、行内代码、图片转成第一阶段的格式标记（`<g1>…</g1>`、`<x2/>`），翻完按原来的符号写回；标记没保住时按纯文本译文写回 -- 丢格式，不丢文字
- **保真**：没翻的部分逐字不动；换行风格（LF / CRLF）、空行、缩进保持原样
- 一个文件的段落一起发给 aitd，回来后按原位置重组

### SRT

- 解析成「序号、时间轴、文字」；一条字幕有多行文字时合成一行翻
- 只要译文时，译文写成一行替换原文；双语时原文在上、译文一行在下
- 只支持 UTF-8（有没有 BOM 都行）；其他编码报错，提示先转成 UTF-8
- 格式不对的条目（比如缺时间轴）报错并给出行号，不猜
