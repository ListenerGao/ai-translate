ai-translate · 架构 V2 · 2026-10-20

一个本机服务，三个入口

第二阶段之后，浏览器插件和命令行 ait 都只连本机翻译服务 aitd：模型、缓存和术语表只有一份。第三阶段加一个 Swift 原生的桌面应用，它也只是 aitd 的又一个客户端。翻译内容始终不出本机。V1（docs/architecture-v1.html）保留不改，本页记录第二阶段的实际结构和第三阶段的做法。

桌面应用（第三阶段）

菜单栏和 Dock 都有图标，最低 macOS 14。用 Swift Package 构建，脚本组装成 ~/Applications/AI Translate.app，用本机自签名证书签名（身份固定，辅助功能授权一次长期有效）。不用第三方 Swift 包。

菜单栏、Dock 和设置（Goal 6）

菜单栏显示 aitd 和模型状态（说法和插件弹窗一致），能打开翻译窗口、翻译剪贴板、翻译文件、设置；设置里改默认语言、术语表（和插件、命令行同一份）、登录时打开。「重启翻译服务」后经 /api/model/load 马上加载模型。

翻译窗口（Goal 6）

左边输入、右边出译文，停止输入 0.5 秒后翻；按空行分段，每段一个 interactive 请求，再次输入时撤销上一次。

文件翻译（Goal 6）

拖入 Markdown、SRT，经 /api/translate-document 走 batch 通道，显示进度，写到原文件旁边，规则和 ait translate 相同。

划词（Goal 7）

任何 App 里选中文字按 ⌥D：先用辅助功能接口读选中文字，读不到再模拟 ⌘C 并恢复剪贴板。另有翻译剪贴板和右键「服务」菜单，不需要授权。

模型管理（Goal 8）

App 从 Hugging Face 下载量化版本（断点续传、sha256 校验），aitd 负责列出、切换和删除。

连 aitd

只连本机地址；密钥从 api-key 文件读，不另存；请求不带 Origin，和命令行一样。

安全边界

  • 翻译内容只在本机：插件、命令行、桌面应用只连 127.0.0.1；外网请求只有下载模型（脚本或桌面应用）和安装依赖。
  • aitd 只监听 127.0.0.1；除 /health 外都要密钥；拒绝非本机 Host 和网页来源；不返回 CORS 头；日志只记事件、计数、耗时和错误码。
  • llama-server 用 aitd 每次启动时生成的一次性密钥，插件、命令行和桌面应用都连不上它。
  • 桌面应用不写日志、不存翻译历史；模拟 ⌘C 取词后恢复剪贴板；辅助功能授权只用来读选中的文字。
  • 密钥只在 ~/Library/Application Support/ai-translate/api-key（权限 600）和插件的 chrome.storage.local；签名证书放在单独的钥匙串文件里，只给这个 App 签名。
